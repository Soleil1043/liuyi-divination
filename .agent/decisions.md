## D001: 技术栈选型 — 2026-10-25

**背景**：纯前端六爻占卜网页（spec v1.0），排盘正确性是项目命门，视觉效果是核心诉求，Windows 单机开发。

**选项**：
| 选项 | 优点 | 缺点 |
|------|------|------|
| A: Vue 3 + Vite + TS + Vitest | 组件化清晰、类型约束引擎数据结构、单测基建现成、产物纯静态 | 需 Node 构建流程 |
| B: 原生 HTML/CSS/JS 零构建 | 零依赖、打开即用 | 无类型、无组件化、无测试基建，引擎无法做 golden 用例 |
| C: React + Vite + TS | 生态最大 | 对单人小项目偏重，无对应收益 |
| D: Svelte 5 + Vite + TS | 内置动画、产物小 | 生态较小，新语法生成代码可靠性存疑 |

**最终选择**：A

**理由**：本项目对"正确性 > 一切"，TS 类型 + Vitest golden 用例是保障排盘正确的关键基建；Vue 3 规模适中、稳定成熟。

**影响**：全部构建任务；T001 脚手架按此初始化。

## D002: 历法干支用 lunar-javascript 而非自实现 — 2026-10-25

**背景**：排盘需要公历时刻 → 干支四柱 + 旬空，涉及节气换月、早晚子时（E04）等历法细节。

**选项**：
| 选项 | 优点 | 缺点 |
|------|------|------|
| A: lunar-javascript（MIT） | 国内最成熟历法库，四柱/节气/旬空齐备，可配置早晚子时 | 无官方 TS 类型，需自写声明文件 |
| B: 自实现历法算法 | 零依赖 | 节气换月等细节极易做错，验证成本远超收益 |

**最终选择**：A

**理由**：历法是排盘最易错的坑，专业库 + golden 用例交叉验证最稳；类型声明成本极小。

**影响**：engine/calendar.ts、lunar.d.ts；golden 用例需覆盖晚子时。

## D003: 历史记录存原始数据、展示时重算，不存快照 — 2026-10-25

**背景**：F05 历史卦例需要保存排盘与解读，可存最小事实（爻值+时间+所问）或完整盘面快照。

**选项**：
| 选项 | 优点 | 缺点 |
|------|------|------|
| A: 存原始数据重算 | 每条 <1KB；算法修正、译文润色后历史卦例自动受益 | 依赖确定性约束（spec 已固化） |
| B: 存完整快照 | 与当时展示完全一致、渲染快 | 数据僵化，改进无法回溯生效 |

**最终选择**：A

**理由**：确定性已列入 spec 技术约束；重算让历史记录随项目质量提升而受益。

**影响**：storage/records.ts 的字段设计；ResultView 与 HistoryView 复用同一引擎路径。

## D004: 视觉风格采用「甲 · 鎏金暗夜」 — 2026-10-25

**背景**：视觉效果是项目核心诉求，需在三方向中定稿：甲鎏金暗夜 / 乙宣纸水墨 / 丙现代极简。

**选项**：
| 选项 | 优点 | 缺点 |
|------|------|------|
| 甲: 鎏金暗夜（墨黑+鎏金+朱砂） | 仪式感最强、与占卜场景契合、动效最出效果 | 暗色下正文对比度需谨慎调校 |
| 乙: 宣纸水墨 | 文人书卷气 | 动效氛围感弱于甲 |
| 丙: 现代极简 | 最克制 | 仪式感最弱，与产品气质不符 |

**最终选择**：甲（用户确认）

**理由**：摇铜钱占卜天然适合暗夜仪式感；鎏金铜钱在墨黑底上视觉冲击最强。

**影响**：ui/theme.css 色彩 token、铜钱 SVG 与全部动效设计。

## D005: 白话译文 AI 起草 + 作者校对、版权自持 — 2026-10-25

**背景**：F04 需要全部 64 卦 + 386 条爻辞的白话译文；现代学者译本（南怀瑾、傅佩荣、黄寿祺等）均在版权保护期，不可爬取使用。

**选项**：
| 选项 | 优点 | 缺点 |
|------|------|------|
| A: AI 起草 + 作者校对自持版权 | 版权干净、文风可控统一、随仓库 MIT 发布 | 需一轮校对工作量 |
| B: 逐项目核实开源汇编白话 | 若核实通过可省校对 | 来源来路不明，逐条核实成本高且风险残留 |

**最终选择**：A（B 作为机会性替换路径：若核实到许可兼容的现成数据可切换）

**理由**：版权干净是开源项目底线；自写译文质量与文风可控。

**影响**：data/hexagrams.json 的 vernacular 字段生产流程（构建期任务）。

## D006: 轻依赖原则——不引 vue-router / Pinia / GSAP / 组件库 / 字体外链 — 2026-10-25

**背景**：3 个视图的小型单页应用，第三方依赖的每一项都要有明确收益。

**选项**：
| 选项 | 优点 | 缺点 |
|------|------|------|
| A: 轻依赖（状态机切视图、CSS/SVG 动画、手写国风样式、系统字体栈） | 产物最小、无外部攻击面、离线可用、维护面最小 | 复杂动画需手写 keyframes；无 URL 路由 |
| B: 引入全家桶（router + Pinia + GSAP + 组件库） | 开发套路化 | 对本项目规模纯属冗余，且组件库风格与国风定制冲突 |

**最终选择**：A

**理由**：自用单页应用，路由/全局状态/重型动画库均无对应需求；零外链保证离线可用。

**影响**：App.vue 顶层视图状态机；theme.css 手写体系；CI 与部署配置更简单。
